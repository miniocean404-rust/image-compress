# rimage/ vs crates/core/src/codecs/ 详细对比

## 1. WebP 编码器

### Options 设计

**rimage** (`rimage/codecs/webp/encoder/mod.rs`):

```rust
/// 直接使用底层库类型别名
```

```rust
pub fn encode_mem(&mut self, buf: &Vec<u8>) -> anyhow::Result<Vec<u8>> { ... }
```

## 5. MozJpeg 编码器

### Options 设计 - 主要差异

**rimage** (`rimage/codecs/mozjpeg/encoder/mod.rs`):

```rust
pub struct MozJpegOptions {
    pub quality: f32,
    pub progressive: bool,
    pub optimize_coding: bool,
    pub smoothing: u8,
    pub color_space: mozjpeg::ColorSpace,
    pub trellis_multipass: bool,
    pub chroma_subsample: Option<u8>,
    pub luma_qtable: Option<QTable>,    // 直接传入 QTable 对象
    pub chroma_qtable: Option<QTable>,  // 直接传入 QTable 对象
}
```

**crates/core** (`crates/core/src/codecs/jpeg/encoder/options.rs`):

```rust
pub type MozJpegColorSpace = mozjpeg::ColorSpace;

pub struct MozJpegOptions {
    pub quality: f32,
    pub progressive: bool,
    pub optimize_coding: bool,
    pub smoothing: u8,
    pub color_space: MozJpegColorSpace,
    pub trellis_multipass: bool,
    pub chroma_subsample: Option<u8>,
    pub luma: bool,                       // 布尔标志：是否应用到 luma
    pub chroma: bool,                     // 布尔标志：是否应用到 chroma
    pub qtable: Option<QtableOptimize>,   // 枚举选择预设量化表
}

#[derive(Debug, Clone, Copy)]
pub enum QtableOptimize {
    AhumadaWatsonPeterson,
    AnnexK_Luma,
    Flat,
    KleinSilversteinCarney,
    MSSSIM_Luma,
    NRobidoux,
    PSNRHVS_Luma,
    PetersonAhumadaWatson,
    WatsonTaylorBorthwick,
}
```

### 量化表应用逻辑

**rimage**:

```rust
// 直接设置传入的 QTable
if let Some(qtable) = luma_qtable {
    comp.set_luma_qtable(qtable)
}
if let Some(qtable) = chroma_qtable {
    comp.set_chroma_qtable(qtable)
}
```

**crates/core**:

```rust
// 根据枚举选择预设量化表，然后根据 quality 缩放
let qtable = match self.options.qtable {
    Some(QtableOptimize::AhumadaWatsonPeterson) => {
        Some(AhumadaWatsonPeterson.scaled(self.options.quality, self.options.quality))
    }
    Some(QtableOptimize::Flat) => {
        Some(Flat.scaled(self.options.quality, self.options.quality))
    }
    // ... 其他预设
    None => None,
};

if let Some(qtable) = qtable {
    if self.options.luma {
        comp.set_luma_qtable(&qtable);
    }
    if self.options.chroma {
        comp.set_chroma_qtable(&qtable)
    }
}
```

### Metadata 处理

**rimage**:

```rust
#[cfg(feature = "metadata")]
{
    if let Some(_metadata) = &image.metadata().exif() {
        log::warn!("Writing exif data is not supported");
    }
    if let Some(metadata) = &image.metadata().icc_chunk() {
        comp.write_icc_profile(metadata);
    }
}
```

**crates/core**:

```rust
#[cfg(feature = "metadata")]
{
    use exif::experimental::Writer;

    if let Some(metadata) = &image.metadata().exif() {
        let mut writer = Writer::new();
        let mut buf = std::io::Cursor::new(b"Exif\x00\x00".to_vec());
        buf.set_position(6);

        for metadatum in *metadata {
            writer.push_field(metadatum);
        }
        let result = writer.write(&mut buf, false);
        if result.is_ok() {
            comp.write_marker(mozjpeg::Marker::APP(1), buf.get_ref());
        }
    }
}
```

**差异**: crates/core 实现了 EXIF 写入功能，rimage 只是警告不支持。

## 8. Operations 模块

### Quantize

两者实现基本相同，都使用 `imagequant` 库。

### Resize

两者实现基本相同，都使用 `fast_image_resize` 库。

**rimage** 支持 `threads` feature 进行多线程处理。

### ICC

两者实现基本相同，都使用 `lcms2` 库。

## 总结：主要差异点

| 模块                      | 差异点      | rimage                      | crates/core                         |
| ------------------------- | ----------- | --------------------------- | ----------------------------------- |
| **WebP Options**          | 类型设计    | 直接使用 `webp::WebPConfig` | 自定义结构体 + `From` trait         |
| **WebP/AVIF/TIFF 解码器** | Trait Bound | `Read` / `Read + Seek`      | `BufRead` / `BufRead + Seek`        |
| **AVIF 编码器**           | 默认 speed  | 6                           | 5                                   |
| **MozJpeg Options**       | 量化表配置  | 直接传入 `QTable` 对象      | 枚举选择预设 + luma/chroma 布尔标志 |
| **MozJpeg 编码器**        | EXIF 写入   | 不支持（仅警告）            | 支持写入                            |
| **所有编码器**            | 便捷方法    | 无                          | 提供 `encode_mem()`                 |
| **Debug trait**           | 实现        | 部分实现                    | 更完整的 Debug 实现                 |

### 需要关注的 rimage 更新点

1. **Trait Bound 变化**: 如果 rimage 将 `Read` 改为 `BufRead`，需要同步更新
2. **Options 字段变化**: 检查是否有新增/删除的配置项
3. **默认值变化**: 如 AVIF speed 默认值
4. **新功能**: 如 metadata 处理的改进
5. **新编解码器**: 检查是否新增了格式支持
